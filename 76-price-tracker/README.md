# 电商比价追踪 Bot

贴商品链接订阅查价，降价超阈值自动提醒，价格历史存 30 天。模式与 23 号币价提醒同构，难点只在数据源——这一篇把边界写在前面。

## 部署要点
单体三步部署，变量：BOT_TOKEN*、PRICE_DROP_PCT（降价提醒阈值百分比，默认 5）、ADMIN_ID（看 /pricestats）、WEBHOOK_SECRET ＋ 必须绑定 KV 变量名 BOT_KV ＋ **必须加 Cron Trigger**（建议 `0 */6 * * *` 每 6 小时；查价太频对源站不礼貌，也容易被限流）。

## 价格解析：站点适配层（重要）
价格只从两个标准位置取，都在 `extractPrice()` 一个函数里：
1. **JSON-LD**：页面 `<script type="application/ld+json">` 里的 `offers.price`（含 @graph/数组形态递归找）；
2. **OG 价格 meta**：`<meta property="product:price:amount">`。

多数独立站、中小电商、Shopify 类店铺都带其中之一，开箱可跑。**Amazon、京东这类大平台**页面是 JS 渲染 + 强反爬，静态 HTML 里没有可靠价格——模板**不做全文正则猜价**（页面数字太多，猜错价比不报更糟），解析不到就当场告诉用户「该站点暂未适配」，且不收订阅。要接大平台，正确姿势是授权 API（如 Keepa）：把 `fetchPrice()` 的实现换成调 API，数据结构 `{price, title}` 不变，其余代码不用动。

## 玩法说明
- /track <链接>：先真抓一次价验证可解析，抓不到不落订阅；同 URL 全局共用一个 `price:item:<id>`（subs 数组扇出），个人清单存 `price:sub:<uid>`，两边双向维护。
- Cron 查价：降幅 ≥ 阈值才推送（涨价/小波动只记历史）；历史按天一个点（同天覆盖），只留近 30 天，存 item.history。
- 抓取安全沿用 44 号口径：SSRF 私有地址字面拦截、10 秒超时、UA 自报家门、单页最多读 500KB。
