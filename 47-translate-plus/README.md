# 翻译进阶 Bot

27 号翻译的升级版：四条管线——文档翻译、语音翻译、图片翻译、群自动翻译，私聊文本互译保留。模块 31 的成品落地版。

## 部署要点
同单体三步部署，变量：BOT_TOKEN*、WEBHOOK_SECRET，加三个可选外部服务（见下）。群自动翻译的开关存 KV，用这个功能才需要绑 BOT_KV；其余管线不用 KV。

## 四条管线
- **文档翻译**：发 .txt/.srt/.md（≤5MB），整篇分段翻译后回传「原名.译文.txt」。docx/pdf 的文本抽取 Workers 本地做不了，会明确提示改发纯文本，不假装支持。
- **语音翻译**：语音 → Whisper 兼容 STT 转写 → 翻译，回原文+译文。需配 STT_API_KEY（STT_API_BASE/STT_MODEL 可选）；**没配时明确提示未配置**，不静默失败。语音上限 5 分钟。
- **图片翻译**：图片 → OCR.space 提字 → 翻译。OCR_API_KEY 不填用免费演示 key helloworld（额度小，回复质量受限）。
- **群自动翻译**：群管理员 /autotr zh|en|ja|ko|ru 开启、/autotr off 关闭；群内异语消息（粗判语言不一致、长度 ≥4）自动回帖译文，开关存 autotr:<群ID>。

另：回复任意消息发 /fy 按消息类型选管线，可带目标语言（/fy ja）；私聊纯文本自动中英互译（27 同款）。

## 翻译引擎
默认 Google gtx 免费接口（非官方、有限流，只适合轻量场景，与 27 同款说明）。配 TRANSLATE_API 可换成自有接口：POST {text, target} 返回 {text} 即可，管线其余部分不用动。

## 注意事项
- 分段翻译会丢跨段指代，长文档连贯性一般，重要文件人工校对。
- 群自动翻译容易刷屏：已过滤短句/命令/纯表情；高活跃群再加节流（思路见模块 27）。
- 语音翻译是 STT+翻译两段外部调用串行，延迟和成本都是双倍，属正常现象。
- 图片里的 TG 文件直链带 Token，只发给 OCR 服务，不落日志。
