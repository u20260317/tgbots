# 论坛话题工单 Bot

30 号工单的话题群组织升级版：一张工单 = 客服超级群里的一个话题，客服在话题里回复即回达用户，用户完全无感。拼装来源是模块 39（论坛话题）+ 模块 30（工单）。

## ⚠️ 前置条件（缺一不可，先看这里）
- 客服群必须是**超级群**，且在群设置里**开启 Topics（话题）功能**；
- Bot 必须拉进群设为**管理员**，并勾上**管理话题**权限；
- FORUM_GROUP_ID 填这个群的 ID（负数，用 08 号 ID 工具查）。
普通群没有话题功能，createForumTopic 会直接报错——上线前先拿测试单实测一遍。

## 部署要点
同单体三步部署，变量：BOT_TOKEN*、FORUM_GROUP_ID*、WEBHOOK_SECRET、ADMIN_ID（/tickets 总览用）＋ 必须绑定 KV 变量名 BOT_KV（与 30 共用同一命名空间也行，键不冲突）。

## 玩法说明
- 用户私聊直接发消息即建单：Bot 在客服群建话题（名字 = 工单号 + 问题摘要），话题里先落一张工单卡（带关单按钮），用户消息随后 copy 进话题。
- 用户后续消息自动续进同一话题（一人同时一张未结单）；客服在话题里发任何消息（文字/图片/文件）都会原样 copy 回用户。
- 结单三种方式：工单卡按钮、客服在话题里发 /close、用户私聊发 /close。结单 = 关闭话题 + 清映射，**不删话题**，历史记录还在，需要时可 reopen。
- 管理员私聊 /tickets 看未结工单总览。

## 注意事项
- General（综合）话题的 thread_id 是 1，Bot 不路由那里的消息，别在 General 里回复工单。
- 话题名上限 128 字，摘要已做截断。
- Bot 被取消管理员后建不了/关不了话题，工单会卡住，权限变动后回归测一遍。
- 与 30 的分工：30 是「卡片+回复路由」的平面客服群；45 是话题群，一单一格、翻记录和交接更清楚。键约定完全兼容（ticket:/userticket:/tmap:），45 另加 topic: 话题映射。
