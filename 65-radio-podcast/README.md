# 电台 / 播客 Bot

电台流目录点播 + 播客 RSS 订阅更新推送，一个 Bot 两件小事。

## 部署要点
同单体三步部署，变量：BOT_TOKEN*、WEBHOOK_SECRET ＋ 绑定 KV 变量名 BOT_KV（存播客订阅；不绑 KV 时电台能用、播客订阅会提示）。
播客推送需给 Worker 加 Cron Trigger，推荐 `*/30 * * * *`（每半小时查一轮）；不配 Cron 订阅只存不推，订阅成功消息里会提醒。

## 玩法说明
- /radio 出电台表（默认 SomaFM 五个公开台，改 worker.js 顶部 RADIOS 表增删），点电台 → 介绍 + 「打开直播流」链接按钮。
- /podcast add <RSS地址> 订阅播客：订阅时先拉一次验证并记住最新单集（不补推历史）；/podcast 看列表；/podcast del 序号 退订。
- 新单集推送：先试 sendAudio 直发音频（Telegram 侧拉取 enclosure 直链），文件太大或拉取失败自动退回带「收听单集」按钮的消息；积压最多补推 3 集防刷屏。

## 平台边界（先说清，免得期待错位）
- **直播电台流不能在 Telegram 聊天里内嵌播放**：Bot 只能给流地址，点开后用浏览器/播放器收听（个别客户端点开 mp3 流链接会自带播放，行为看客户端）。想要「点按钮就在聊天里播」的电台 Bot 不存在，那是客户端能力不是 Bot 能力。
- 播客单集是普通音频文件，可以正常发进聊天，限制是 Telegram 对「按 URL 拉取文件」的大小上限（约 20MB），超了就走链接消息兜底。

## 注意事项
- RSS 解析是正则实现（复用模块 15 姿势），覆盖标准 RSS 2.0 播客源；结构怪异的源可能解析不到 enclosure，订阅时会直接报错而不是假装成功。
- 电台流地址是第三方公开流，稳定性归电台方；失效了换 RADIOS 表里的 url 即可。

## 拼装来源
模块 15（RSS 抓取解析）+ 模块 09（Cron 定时任务）+ 模块 01（骨架）。与 11（RSS 推频道）区别：11 把资讯推给频道，65 把播客单集推给订阅者个人。
