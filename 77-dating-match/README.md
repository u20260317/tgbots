# 相亲交友 Bot

> ## 🛡️ 安全设计（先读这段，这是本模板的本体不是附注）
> 1. **未成年禁入**：建卡第一步是 18+ 按钮确认，未确认进不了表单；年龄填 <18 直接拒绝并清状态。Bot 能做的只是声明+自报校验，运营者仍须在社群规则里明示并巡查。
> 2. **举报自动封禁**：每张卡带 🚩 举报按钮，被**不同用户**举报达阈值（`DATE_REPORT_LIMIT`，默认 3）自动封禁、下架档案并通知管理员；管理员可 /dateunban 解封、/dateban 手动封。
> 3. **敏感词过滤**：介绍与城市过 CONFIG 敏感词表（留微信、刷单、博彩、裸聊类招揽词），命中打回。
> 4. **媒体可关**：`DATE_MEDIA_OFF=1` 时全站禁照片（建卡跳过照片步、卡片纯文字），冷启动建议先开。
> 5. **联系方式最小化**：配对前双方互不可见任何联系方式；配对后只推 Telegram **公开用户名**链接，Bot 不存、不转交手机号等信息。/start 里写有防诈骗须知（索要转账/投资/代充即诈骗）。
>
> ⚠️ 交友类是诈骗与骚扰高发区：模板给的是「能落地的最低安全线」，不是免责声明。真运营请配真人巡查与本地法规核查（婚介资质、个人信息保护）。

档案卡 + 滑动互选 + 双向喜欢才配对，形态对标 Leo Match 一类。

## 部署要点
单体三步部署，变量：BOT_TOKEN*、DATE_REPORT_LIMIT（举报封禁阈值，默认 3）、DATE_MEDIA_OFF（=1 禁照片）、ADMIN_ID（封禁通知与管理命令，**强烈建议填**）、WEBHOOK_SECRET ＋ 必须绑定 KV 变量名 BOT_KV。无需 Cron。

## 玩法说明
- 建卡 FSM（状态存 `date:step:<uid>`）：18+ 确认 → 性别 → 想找 → 年龄（18-99 校验）→ 城市 → 介绍（敏感词过滤）→ 照片（可跳过）→ 落 `date:prof:<uid>`。
- /browse 候选挑选：性别互配（seek 与 gender 双向对上）、排除自己/已封禁/已看过（`date:seen:<uid>`，喜欢与跳过都记）；卡片按钮 ❤️/⏭/🚩（回调 `date:` 前缀），每次操作后自动翻下一张。
- 配对：喜欢存 `date:like:<uid>`；发现对方也喜欢我 → 双方各推一条配对通知（档案卡 + t.me 公开用户名按钮）。/matches 随时重看配对列表。
- 举报计数存 `date:rep:<目标uid>`（举报者名单去重），封禁标记 `date:ban:<uid>`，被封者全功能拦截。

## 规模与边界
- 候选挑选靠全量扫 `date:prof:` 前缀，千级档案内没问题；上万用户要加性别分桶索引或换 D1，属部署后演进项。
- 年龄是自报，Bot 无法核验真实年龄——这是所有交友 Bot 的共同边界，靠举报与巡查兜底，别在宣传里承诺「已实名」。
