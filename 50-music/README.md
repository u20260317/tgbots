# 音乐下载 / 识曲 Bot

贴链接下音频 + 发片段识曲，与 34 号视频下载同一条解析管线、换成音频出口。模块 44 的成品落地版。

## ⚖️ 版权边界（先看这行）
只处理公开可访问、你有权下载的内容；**不绕 DRM、不破付费墙、不做盗版资源分发**。解析层是外部服务，Bot 只做通道；用户提供链接的内容责任在提供方，Bot 的说明与 caption 里都写明了这条口径。

## 部署要点
同单体三步部署，变量：BOT_TOKEN*、WEBHOOK_SECRET、MUSIC_RESOLVER_API（可选）、AUDD_API_TOKEN（可选，Secret）、DAILY_LIMIT（默认 10）、ADMIN_ID ＋ 必须绑定 KV 变量名 BOT_KV（限额 `mus:cnt:`、累计 `mus:`，新前缀，已查模块 04 注册表避冲突）。

## 玩法说明
- 发音乐/视频链接：解析层只要音轨（cobalt 兼容协议 downloadMode=audio），sendAudio 回传成歌曲卡片；超 50MB 或 TG 拉不动时回直链。
- 发语音/音频片段（5–15 秒最准）：AudD 指纹识曲，回歌手/歌名/专辑/发行日期与平台链接，口径是「最接近的是」；回复音频发 /whatsong 同理。
- 每人每天下载+识曲共用 10 次额度（DAILY_LIMIT 可调）；管理员 /musstats 看累计使用。

## 两个外部服务各自独立
- MUSIC_RESOLVER_API 没配：下载走演示模式，动手时明确提示（与 34 同惯例）。
- AUDD_API_TOKEN 没配：识曲明确提示未配置。
- 缺哪个只关哪个功能，另一个照常工作。

## 注意事项
- 解析直链带时效和防盗链，拿到立刻用、不存 KV 复用；失败如实回退直链。
- 识曲对片段质量敏感：太短、噪音大、翻唱/现场版都可能认错或认不出，这是技术边界。
- AudD 按次计费，所以识曲和下载共用同一个限额池，别只给下载设闸。
