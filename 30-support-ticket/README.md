# 客服工单 Bot

带编号和状态的客服工单：用户发消息即开单，工单卡进客服群，多人客服协作回复，点按钮关单。比 02 双向 Bot 更适合有客服团队的场景。

## 部署要点
同单体三步部署，变量：BOT_TOKEN*、ADMIN_ID*、SUPPORT_CHAT_ID（客服群 ID，推荐配群；不填则工单卡发第一个管理员私聊）、WEBHOOK_SECRET ＋ 必须绑定 KV 变量名 BOT_KV。客服群 ID 用 08 号 Bot 查（把 Bot 拉进群发 /id 类命令），Bot 需在客服群里。

## 流程
- 用户私聊发任意消息（或 /ticket 描述）→ 建单 TK-xxxx，卡片发客服侧，用户收到编号
- 用户后续消息自动续到同一张未关闭工单（复制转发并挂在工单卡下）
- 客服：在客服群里**回复**工单卡或工单下任意一条转发消息 → 内容直达用户
- 客服点卡上「✅ 关闭工单」→ 工单关闭并通知用户；用户再发消息会开新单
- /tickets（客服侧发）列未关闭工单；用户 /myticket 查自己工单状态

## 说明
- 一人同时只有一张未关闭工单（userticket 索引），不会重复开单刷屏客服群。
- 路由靠 KV 的 tmap 映射（客服侧消息 ID → 工单号），所以客服回复时务必用「回复」功能，普通发言不会转发。
- 客服群模式下任何群成员回复都会被转发给用户，请只把客服人员放进客服群。
