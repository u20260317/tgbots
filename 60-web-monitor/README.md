# 网站更新监控 Bot

盯没有 RSS 的网页：定期抓正文、算哈希、和上次快照比对，变了就推 diff 摘要。是 11（只认 RSS/Atom）的盲区补位，对应 Visualping / changedetection.io 的告警形态。

## 部署要点
同单体三步部署，变量：BOT_TOKEN*、WEBHOOK_SECRET ＋ 必须绑定 KV 变量名 BOT_KV。
⚠️ 必须加 Cron Trigger，推荐 `0 * * * *`（每小时）；单个监控另有 MIN_INTERVAL_MIN（代码 CONFIG，默认 55 分钟）兜底，Cron 再勤也不会重复抓同一个页面。

## 玩法说明
- /watch <网址>：当场抓一次存基线快照（正文前 8000 字 + SHA-256），之后每小时比对；
- 变化推送长这样：`🔔 网页有更新` + 新增/删除行数 + 前 3 行变化示例（行级集合 diff）；
- /watchlist 列表（带取消按钮），/unwatch <ID> 命令取消；
- 抓取连续失败 3 次只通知一次，恢复后自动闭嘴，防源站宕机刷屏。

## 省流建议（Workers 免费版必读）
- 免费版每天 Cron 触发与子请求都有额度：每个监控每小时 1 次抓取 = 每天 24 次子请求，**监控数先控制在 20 个以内**；
- 想更省：把 Cron 改成 `0 */3 * * *`（3 小时一轮）并把 MIN_INTERVAL_MIN 提到 170，时效性要求不高的页面完全够用；
- 正文归一化（剥脚本/导航/广告位、压空白）后再算哈希，页面上的时间戳、随机广告这类假变化大多会被滤掉，但带动态区块的页面仍可能误报，重要页面建议人工复核推送里的 diff 示例。

## 注意事项
- 抓取礼仪：UA 是带项目地址的固定标识（CONFIG.UA），不伪装浏览器、不绕 robots 的封禁策略；源站明确拒绝抓取时请停用该监控。
- SSRF 防护与 44 同口径：内网/本地地址直接拒绝。
- 纯 JS 渲染的页面抓不到正文（无浏览器渲染能力），建监控时就会报错，不会假装在盯。
