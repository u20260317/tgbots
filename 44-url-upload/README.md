# URL 上传转存 Bot

把外网链接里的文件搬进 Telegram：先体检+安全拦截，再按大小三路分流转存，成功后给取件链接。和 06 文件分享的区别：06 存的是已经在 Telegram 里的文件，本 Bot 处理外网文件第一次进 Telegram——模块 40 的成品落地版。

## 部署要点
同单体三步部署，变量：BOT_TOKEN*、WEBHOOK_SECRET、BOT_USERNAME（可选，拼取件链接）。KV 可选：绑定 BOT_KV 后转存成功自动存档并回取件链接；不绑也能转存，只是不存档。

## 玩法说明
- 直接贴链接，或 /up <链接>，Bot 先回「转存中」再发文件。
- 分流逻辑：≤20MB 让 Telegram 服务器直抓 URL；直抓失败或 20–50MB 由 Worker 中转上传；>50MB 回原链接并说明原因。视频按 sendVideo 发（可播放），其余按文件发保原样。
- 转存成功（绑 KV 时）回一个 `https://t.me/<Bot>?start=f_<码>` 取件链接，任何人点开即可领取，键格式与 06 完全同约定（f:<码>），两个 Bot 可以共用一个 KV 互相取件。

## 安全设计
- 只许 http/https；localhost、.local、10/8、172.16/12、192.168/16、169.254/16、::1 等私有/保留地址字面拦截（SSRF 防护，Bot 的 fetch 是服务器身份，不能当扫内网的跳板）。
- 动手前先 HEAD 体检大小与类型，超限当场拒绝；下载带 60 秒超时掐断。
- 已知边界：字面拦截挡不住「域名解析到内网」的绕法，高安全场景应再加解析后校验，代码注释里有标注。

## 注意事项
- 路线 A 的 20MB 是 Telegram 抓 URL 的经验上限而非官方承诺，所以直抓失败自动降级中转，别删这段兜底。
- 中转把整文件读进 Worker 内存，接近 50MB 时内存和时长都吃紧；真要搬大文件请自建 Local Bot API Server（上限 2000MB）。
- 防盗链站点（Referer/UA 校验）两条路线都可能吃 403，如实报错，不做伪装绕过。
- 转存内容的版权与合规责任在链接提供者，Bot 只做通道。
