# 求职招聘 Bot

企业向导发岗 + 管理员审核上架，求职者搜索投递，零外部依赖（不接任何招聘平台 API）。

## 部署要点
同单体三步部署，变量：BOT_TOKEN*、ADMIN_ID*（审核靠它，没配管理员职位永远过不了审，提交时 Bot 会提醒）、WEBHOOK_SECRET ＋ 绑定 KV 变量名 BOT_KV（不绑 KV 不能用）。
过期清理需给 Worker 加 Cron Trigger，推荐 `0 2 * * *`；不配 Cron 也能用，只是职位不会自动过期。

## 玩法说明
- 企业 /postjob（私聊）：五步向导 标题→城市→薪资→联系方式→介绍（可「跳过」），/cancel 随时退出。提交后生成待审职位，管理员收到带 ✅/❌ 按钮的审核卡，点按钮过审/拒绝，结果通知发布者；管理员也可用 /pending 集中看待审。
- 求职者 /jobs 看全部在架职位，/jobs 北京 或 /jobs 北京 司机 按城市+关键词筛（匹配城市/标题/介绍）。
- /apply 职位ID：进入投递态，下一条消息（文字简历或文件）用 copyMessage 原样转给企业，并把企业联系方式回给投递者。联系方式不出现在公开列表里，减少被爬骚扰。
- /myjobs 看自己发布的（含状态），/deljob 职位ID 删除（只能删自己的，管理员可删任意）。
- 职位 30 天过期：Cron 删除并通知发布者重新发。

## 注意事项
- 审核是人工的：ADMIN_ID 没配 = 审核通道关闭，Bot 在提交时会明说，别指望自动上架。
- 这是「雇主发岗板」形态（SURVEY2 里零外部依赖的那种）；另一种「聚合 hh.ru/RemoteOK 职位源推送」形态需要接源 API，不在本模板内，要做时在 listJobs 前加一层同步即可。
- 防垃圾全靠审核 + 30 天过期；量大了建议给发布者加频率限制（按 job: 键计数，照 64 的限额姿势）。

## 拼装来源
模块 20（FSM 状态机）+ 模块 10（审核流）+ 模块 07（转发与回复路由）+ 模块 01（骨架）。与 18（频道导航）同构：都是「提交 → 审核 → 上架目录」，18 收频道、69 收职位。
