# 11 · 调试与运维

## 本篇讲什么

Bot 不说话了、按钮死了、消息重复了——怎么系统地查而不是瞎试。包括官方自检工具、更新回放测试、日志与可观测性、灰度与回滚姿势，和一张覆盖最高频故障的排查表。

## 核心概念

### 先分清「哪一段」坏了

消息链路有四段：用户 → Telegram →（webhook 投递）→ 你的代码 →（API 调用）→ Telegram → 用户。排障第一步是定位段：

- **getWebhookInfo** 是官方 X 光：看 `url` 对不对、`pending_update_count`（积压多少条没投出去）、`last_error_date` 与 `last_error_message`（最近一次投递失败的原因，如证书、404、超时）。九成「Bot 没反应」在这里就有答案。
- **getMe** 验 token 本身有效且是预期的那个 Bot（串号部署时有奇效）。
- **getUpdates**（轮询模式下）能把积压更新拉出来看原文——注意它与 webhook 互斥，调试前先 deleteWebhook，调完记得设回来。

### 回放测试：不用真人点手机

更新本质是 JSON，完全可以构造假更新喂给你的端点做回归：模拟 /start、按钮回调、付款事件，断言代码发出的 API 调用是否符合预期。本库的全量测试就是这么做的（模拟管理员与假 chat，不打扰真人），本地 harness 还能拦住出站 fetch 逐条核对——方法论与记录在 docs/TESTING.md。原则：**每次改模板，先回放核心路径再部署**。

### 日志与可观测性

- Workers 侧：用平台日志（wrangler tail / 控制台）看实时请求与报错；生产环境保留错误日志、关掉详细调试日志（隐私与成本，见 09 篇脱敏）。
- 业务侧埋三个数：处理过的更新数（按类型）、API 失败数（按 error_code）、429 次数。这三个数能提前一周告诉你限流与故障苗头。
- 告警走 Bot 自己的强项：异常摘要推到管理员的 Telegram（模板 20 的推送 API 就是干这个的）。

### 灰度与回滚

- Worker 部署即生效，回滚要快：保留上一版代码（Git 里每个版本都有），出问题先回滚再复盘，别在线上现改。
- 新功能先用功能开关在小范围开（管理员自己、单个测试群），观察一轮再全量——开关就是配置里的一个布尔值，成本几乎为零。
- 改命令表、改 allowed_updates 这类「注册型」变更，部署后要重新走一遍 /setWebhook 才生效，别漏。

## 故障排查表（按出现频率）

| 症状 | 先查 | 常见根因 |
|---|---|---|
| Bot 完全没反应 | getWebhookInfo | webhook 没设/地址错；secret 不一致；证书问题；pending 积压爆了 |
| 私聊正常、群里没反应 | BotFather 隐私模式 | 隐私模式开着时 Bot 只收命令与回复；关掉或教用户用命令 |
| 按钮点了转圈/无反应 | allowed_updates、回调日志 | 漏订 callback_query；回调抛错；没回 answerCallbackQuery |
| 同一消息处理两遍 | 投递日志、幂等键 | 端点没先回 200 导致重试；关键动作没去重 |
| 命令菜单不对/没更新 | setMyCommands 是否重跑 | 改完命令表没重新注册；客户端缓存 |
| 发图/文件失败 | file_id 来源 | 跨 Bot 串用 file_id；文件超限；原文件形态不对 |
| 群里查不到成员/踢不动人 | Bot 的群权限 | 不是管理员或缺对应权限（邀请/封禁/删消息分开给） |
| chat_member 事件不来 | 权限 + allowed_updates | 两样缺一不可（见 03 篇） |
| 付款卡住 | pre_checkout 处理时长 | 复核超时（约 10 秒）或没答复；金额不一致被自己拒了 |
| 定时任务不跑 | Cron 配置、时区 | Cron 用 UTC 写错时间；触发器没绑到这个 Worker |
| 部署后 1010/403 类错误 | 请求来源 | 用脚本直连某些域名被拦，换正规客户端/工具验证（本库部署工具就踩过） |

## 实操要点

1. 排障顺序固定：getWebhookInfo → 隐私模式/权限 → allowed_updates → 代码日志。按这个顺序，多数问题十分钟内定位。
2. 保留一个「测试 Bot + 测试群」做所有新功能的首发环境，生产 Bot 只上验证过的代码。
3. 每次事故记一行到测试/运维记录：症状、根因、修法——下次同类问题直接查表（本库 docs/TESTING.md 就是这个习惯的产物）。
