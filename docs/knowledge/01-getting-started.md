# 01 · 零基础入门

## 本篇讲什么

Bot 到底是什么、怎么出生、token 是什么东西、一条消息从用户手机到你的代码再回去的完整旅程。读完这篇，你脑子里应该有一张不会错的地图，后面所有篇都是在这张地图上放大细节。

## 核心概念

### Bot 不是账号，是 API 身份

普通用户账号（user）是人用的，要手机号注册、受客户端协议（MTProto）驱动；Bot 是**给程序用的身份**：没有手机号，不能主动给人发消息（必须用户先开口或在群里），一切行为都通过 Telegram 提供的 **Bot API**（一套 HTTPS 接口）完成。你不需要「登录」Bot，你只需要证明「我是这个 Bot 的主人」——靠 token。

### 心智模型：一张图看懂全部

```
用户手机上的 Telegram
      │  ① 用户发消息
      ▼
Telegram 服务器（消息先到这里，排队等你的代码来取/来接）
      │  ② 通过 Webhook 把「更新」推给你的代码
      ▼
你的代码（本库是 Cloudflare Worker 里的 worker.js）
      │  ③ 你的代码调用 Bot API 说「回复他这句」
      ▼
Telegram 服务器 ──④──► 用户收到回复
```

关键推论：

- **你的代码不在线，消息不会丢**：更新在 Telegram 侧排队（保留时长以官方为准），你的服务恢复后还能收到——但别依赖它当数据库。
- **Bot 只能被动响应 + 有限主动**：用户先私聊过 Bot、或 Bot 在群里，才有对话的「地址」（chat_id）。凭空给陌生人发消息是不行的，这也是平台反垃圾的根设计。
- **一切都是 API 调用**：发消息、删消息、查成员、收钱，全是 HTTPS 请求。所谓「写 Bot」，就是写「收到更新 → 决定调用哪些 API」的逻辑。

### BotFather：Bot 的户口本

@BotFather 是官方的 Bot 管理机器人，所有 Bot 都从它这里出生：

- `/newbot` 建号：起名字（name，可改）和用户名（username，以 bot 结尾、全局唯一、基本不可改，慎重）。
- 它发给你的 **token** 长这样：`123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`——冒号前是 Bot 的数字 ID，冒号后是密钥。**token = 这个 Bot 的全部权限**，谁有 token 谁就是 Bot 本人。
- BotFather 还管：头像、简介、命令列表默认值、是否允许进群、群隐私模式、Inline 模式开关、Mini App 入口等。很多「为什么不生效」的问题根源在 BotFather 设置，不在代码（见 11 篇排障表）。

### 三个最先要认识的 ID

- **user id**：用户的数字 ID，终身不变（用户名会变、会没有）。鉴权、记账都认它。
- **chat id**：一次对话的地址。私聊的 chat id = 对方 user id；群是负数，超级群/频道是 `-100` 开头的大负数。
- **message id**：消息在所属 chat 内的编号（每个 chat 独立计数），编辑/删除/回复都靠它 + chat id 定位。

## 实操要点

1. 建 Bot 后第一件事：把 token 存进密码管理器或部署平台的 Secret，**不要**贴进聊天、代码仓库、截图。
2. 先私聊你的 Bot 发一句 `/start`——这一步建立了「Bot 可以给你发消息」的通道，后面调试全靠它。
3. 拿不准任何 ID 时，用库里的 08-id-tools 模板查，它就是为这个造的。
4. 给 Bot 起名时想好 username：它会出现在所有链接（t.me/<username>）和深链里，改不了。

## 常见坑

- **把 token 发到群里/提交进 Git**：等于把 Bot 送人。泄露后立刻去 BotFather 用 `/revoke` 作废重发，旧 token 当场失效。
- **以为 Bot 能主动加人/拉群/私信陌生人**：都不能。这是设计，不是你代码的问题。
- **在群里 @Bot 没反应**：多半是群隐私模式（见 03、11 篇），不是 Bot 坏了。
- **拿用户名当唯一标识**：用户名可改可注销，数据库里存 user id，用户名只做展示。
