# 16 · Bot 测试方法论

## 本篇讲什么

Bot 为什么特别难测、本库是怎么测的：模拟更新回放、本地 harness 拦出站调用、KV 副作用读回这三板斧，以及贯穿四轮全量实测的 L1–L5 分级标准是怎么来的、怎么用。

## 核心概念

### Bot 为什么难测

普通后端测试难在依赖多，Bot 还要再叠三层：

- **没有「界面」可点**：交互全是异步事件（消息、回调、支付事件），测试要先把「用户做了什么」翻译成 Update JSON 才谈得上喂给代码。
- **真正的外部世界不可控**：Telegram 的投递会重试、KV 是最终一致、第三方 API 会限流——同一个测试跑两遍结果可能不同，要先学会区分「代码 bug」和「环境抖动」。
- **副作用不在返回值里**：Bot 的 fetch 只回一个 200，真正的产出是它调出去的那些 API 和写进 KV 的状态。不验证副作用的测试，等于只验了「没崩」。

### 三板斧

**一、模拟更新回放。** 更新本质是 JSON，构造假更新（模拟管理员 ID、假 chat id）打给已部署的 Worker webhook，驱动真实代码走完整路径。好处是跑的是线上同款代码与绑定；约束是绝不打扰真人——全程假 ID，Bot 真发出去的消息只会落到不存在的 chat 上报错，正好无害。

**二、本地 harness。** 把 worker.js 拷成 .mjs 在 Node 里 import，stub 掉全局 fetch 拦截它对 Telegram 的出站调用，逐条断言「该发的 sendMessage 发了没、参数对不对」，再配一个 Map 假 KV 观察读写。适合验参数构造（比如 quiz 的 correct_option_id 换算）和不方便真部署的分支（支付签名、游戏记分令牌）。

**三、KV 副作用读回。** 凡是声称「落盘了」的功能，测完必须用 CF API 把键读回来核对内容——签到分对不对、订单状态流转到哪、快照 hash 与独立复算是否一致。**「回复文案说成功了」不算证据，读回的键值才是。** 本库四轮战役里多个「假成功」就是被这一步揪出来的。

### L1–L5 分级标准

| 级 | 验什么 | 通过标准 |
|---|---|---|
| L1 | 语法 | node --check 通过、格式化无异常 |
| L2 | 部署 | 真部署成功、健康检查 200、setWebhook 成功 |
| L3 | 行为 | 模拟更新驱动核心命令/回调，分支行为符合预期 |
| L4 | 副作用 | KV 读回 / 出站调用断言，状态与预期逐项一致 |
| L5 | 真人 | 真人真机完整走一遍真实场景 |

分级的意义是让「测过了」这句话有刻度：一个模板标 L4，意味着它的状态落盘被独立读回核对过；只到 L3 的，说明行为对但副作用没验穿（多半是受真实外部条件所限），记录里必须写明边界在哪。本库 85 个对象全部至少 L4，签到模板由用户真人测到 L5。

### 边缘传播抖动：最常见的假警报

Cloudflare 新部署的 Worker 与新绑定的 KV 有传播期，实测中反复出现三类「看起来像 bug」的现象：

- **首打 404/500**：新 Worker 第一次请求打到还没同步好的边缘节点，等几十秒复打即恢复。
- **setWebhook 1042 一类错误**：部署后立刻注册 webhook 偶发失败，sleep 后用同一密钥重打即成功。
- **KV 读回延迟**：刚写进去的键立刻读不到或读到旧值（见 17 篇），等待复读再下结论。

识别口诀：**只出现一次、等待后自愈、且与代码路径无关的失败，先按抖动处理并复测**；稳定复现的才是 bug。本库四轮里被这样澄清的假警报有十余起，误判任何一起都会白改代码。

## 实操要点

1. 每测一个模板就回填记录（本库是 docs/TESTING.md 一行），别攒到最后——细节凉了就再也写不准。
2. 测试顺序固定：L1 语法 → L2 部署健康 → L3 核心路径回放 → L4 读回 → 记录定级与边界。跳步的测试结论不可信。
3. 抓到 bug 的修法闭环：改代码 → 格式化 → 语法检查 → 推送 → **重新部署复测同一用例** → 记录里写明修法。只改不复测等于没修。
4. 外部 API 类功能（支付、解析、识曲）默认验两条路：未配置时的明确提示分支，和 harness/stub 下的成功分支；真 key 实测受共享出口限流影响时如实记录，不硬凑。

## 常见坑（都是真案例）

- **只看回复不读回**：36 号提醒模板曾把提醒文本存出前导空格，回复文案看不出、读回 KV 一眼现形——副作用验证的价值就在这种地方。
- **把并发问题当偶发**：41 号狼人杀快速连点报名丢人，单步慢测永远测不出，要刻意连打同一动作（见 17 篇复盘）。
- **被环境 403 误导方向**：81 号域名监控查不到数据，根因是出站请求缺 User-Agent 被对方拒，与业务代码无关——先分清「我的代码错了」和「世界不配合」。
- **测试污染生产**：拿真人用户 ID 做模拟会真发消息骚扰人。全程假 ID、独立测试 Bot、独立测试 KV，是底线不是讲究。
