# 房产租售提醒 Bot

按城市/户型/预算订阅房源，有匹配的新房源去重推送。模板给的是订阅-筛选-去重-推送的完整骨架，数据源按市场自接。

## 部署要点
同单体三步部署，变量：BOT_TOKEN*、WEBHOOK_SECRET、ESTATE_API_URL / ESTATE_API_KEY（选填但决定有没有真数据）＋ 绑定 KV 变量名 BOT_KV（不绑 KV 不能用）。
推送需给 Worker 加 Cron Trigger，推荐 `*/30 * * * *`。

## 数据源：为什么只有适配位（区域化现实）
房产门户**高度区域化**：波兰是 Otodom、国内是贝壳/安居客、以色列是 Yad2……没有统一 API，多数门户也不开放接口。所以模板不内置任何市场的抓取，只留一个约定口径的适配位：
- `ESTATE_API_URL`：你的房源服务地址（自建聚合、授权数据商、或你被允许抓取的源的自有中转）。Bot 会 GET `{ESTATE_API_URL}?city=<城市>&rooms=<户型>&max=<预算>`，期望返回 JSON 数组（或 {listings}/{data} 包一层），元素含 id/title/price/rooms/url。
- `ESTATE_API_KEY`：可选，Bearer 头带上。
- 只接**授权 API 或明确允许抓取**的源，不做绕反爬的数据获取——这是 SURVEY2 定下的口径。
- **未配置时的实际行为**：走内置 3 条演示房源，每条都标注，推送文案带「非真实房源」提示，只用来验证订阅→筛选→去重→推送流程。不会假装是真房源。

## 玩法说明
- /watch 上海 2室 8000：订阅（预算口径与数据源统一：租填月租、售填总价）。订阅后立即试拉一次给反馈，之后 Cron 每轮拉取，匹配且没推过的才推（每条订阅每轮最多 5 条）。
- /estates 看订阅列表；/unwatch 序号 取消（连同去重记录一起清）。
- 去重存 `estate:seen:<用户>:<订阅ID>`，滚动保留最近 300 个房源 ID。

## 注意事项
- 户型匹配是宽松包含（订阅「2室」匹配房源 rooms 字段含 2 的），数据源的 rooms 写法（2BHK、2-room）要在你的适配服务里先归一成「N室」再返回，Bot 侧 matchListing 只有这一层。
- 房源时效性强，Cron 别设太疏；但拉取频率受你的数据源额度约束，两边权衡。
