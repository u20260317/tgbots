# 图片处理 / OCR Bot

发图提字、改尺寸、转格式、生成引用图。Workers 没有本地图像引擎，全部外包给外部服务，Bot 只做编排——模块 37 的成品落地版。

## 部署要点
同单体三步部署，变量：BOT_TOKEN*、WEBHOOK_SECRET、OCR_API_KEY（可选）、OCR_LANG（默认 chs）、QUOTE_API（可选）。KV 可选：绑了 BOT_KV 就按天计用量（键 `ocr:cnt:<用户>:<日期>`，新前缀，已查模块 04 注册表避冲突），不绑不影响功能。

## 玩法说明
- 私聊直接发图 = OCR 提字，回帖给出识别文本。
- 群里回复图片：/ocr 提字（可带语言码 /ocr eng）、/resize 800 600 改尺寸、/format webp 转格式（png/jpg/webp，以文件回传保原质）。
- 回复一条文本消息发 /quote 生成引用图（头像+名字+气泡排版）。

## 外部服务说明
- **OCR**：OCR.space 免费接口。未配 OCR_API_KEY 时自动用官方演示 Key `helloworld`——额度极小、速度慢，仅供试玩，回复里会注明；正式使用去 ocr.space 免费注册一个 Key 填上即可。
- **改尺寸/转格式**：wsrv.nl 公共图片代理，免费但可能限流，失败会提示稍后再试。
- **引用图**：需要自备渲染服务（POST JSON → 返回 PNG），地址填 QUOTE_API；没配时 /quote 明确提示未配置，不会假装处理。

## 注意事项
- TG 文件直链带着 Bot Token，只发给上述处理服务，不落日志、不回显；敏感图片（证件、聊天记录截图）慎发第三方 OCR，README 里提醒用户自行判断。
- 手写体、低清截图、复杂表格识别率会明显下降，回复口径是「仅供参考」。
- 大图（>10MB）先经代理缩一版再处理，别整张拉进 Worker 内存。
