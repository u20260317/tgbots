# 23 · 商城连锁（加盟多租户商店）模块

> 商城 = 模块 21（母体托管）× 模块 22（商店系统）。总部运营平台，加盟商交出自己 Bot 的 token 就克隆出一家独立门面的店：Bot 的名字、头像、客户都是加盟商的，系统、托管、升级由总部统一提供。TGTools Reseller、sh0p.bot、BotLaunch 都是这个模式，俄语区一年能评测 20 家同类构造器——是被市场验证过的品类。

## 总部与连锁店怎么分（两种通行模式）

| 维度 | 统供型（TGTools 型） | 自营型（sh0p.bot 型） |
|---|---|---|
| 商品 | 总部批发目录，加盟商选品+设加价 | 店主自建商品，总部不碰目录 |
| 收款 | 进店主绑定通道，总部赚批发差价 | 钱直达店主钱包，平台不经手 |
| 平台收入 | 批发差价 | 订阅费（如 Premium 月费）、去水印费 |

**建议：自营为主 + 总部货源池可选**——总部维护一份推荐目录，连锁店可一键上架到自家店（价格可改），既有连锁统一感，又保住加盟商自主权。

## 在母体之上的增量

租户记录扩商店字段即可，母体的入驻/分发/加密全部复用：

```js
// bot:<slug> 的 config 里加商店字段
config = {
  shopName: "小明的店",          // 店面品牌
  catalogMode: "self",           // self=自营目录 / hq=总部货源池 / mixed
  markupPct: 20,                 // 用总部货源时的默认加价（店主可改单品价）
  payProvider: "stars",          // stars=模块24 / manual=模块13
  supportContact: "@owner",      // 店主客服，显示在子 Bot 里
  watermark: true,               // 免费版带总部水印，付费去水印（行业惯例）
}
```

总部后台（在母体 Bot 里，只有总部管理员可用）：入驻审核（类目准入）、店铺列表与状态、聚合统计（默认只看汇总，不看店内明细）、公告下发、**一键停店熔断**——熔断就是把租户记录的 `stopped` 置 true，模块 21 的分发入口会静默吞掉该店全部更新，先停后查。

## 风险（比母体更重，务必读）

- 🔴 **绝不代收代付**：买家付款必须直达店主自己的支付通道。平台先收钱再结算给店主 = 资金池，涉及支付牌照与挪用风险；sh0p.bot、BotLaunch 都刻意用「钱直达店主」做信任卖点，正是为避开这一点。总部收入只走订阅费/批发差价两条干净通道。
- 🔴 **连锁店违规牵连母体**：某家店卖违禁品、搞诈骗、发垃圾，举报和封禁可能波及母体 Bot、域名与共用出口，最坏全网陪葬。对策：入驻类目审核 + 禁售类目清单 + 举报直达总部 + 熔断停店 + 入驻协议写明「经营责任归店主、平台有权停店」。
- 🔴 token 集中代管是最高价值攻击目标：沿用模块 21 的加密/掩码/不落日志，并加母体管理员操作审计（谁在何时停了哪家店，要留痕）。
- 🟠 平台单点：母体挂 = 全网店停摆；免费额度全店共享，大店挤小店——按租户限流（模块 27），规模上来尽早评估付费计划或分片。
- 🟠 数据归属要在入驻协议里写清：客户与订单归店主，退出可导出、平台删除其 token 密文与数据。BotLaunch/BotHost 都把导出/迁移当卖点，说明商家最在意这个。
