# 29 · 多语言（i18n）模块

> 同一个 Bot 服务多语言用户：按用户 Telegram 客户端的 language_code 自动选语言包，文案全部外置成字典，命令菜单也能按语言分别注册。

## 原理

每条消息的 `msg.from.language_code` 是用户客户端语言（如 `zh-hans`、`en`、`ru`），拿它选语言包是最省事的默认策略；用户手动切换过语言时，以他存下来的选择为准。所有面向用户的文案不写死在代码里，统一放进 `STR` 字典：`STR[语言][键]`，取词函数 `t()` 负责查字典 + 模板变量替换 + 缺词回退。命令菜单的多语言靠 setMyCommands 的 `language_code` 参数：同一组命令按语言各注册一遍描述，用户客户端是什么语言就看到什么描述。

## 代码

```js
// ============================================================
// 【核心模块】多语言文案包
// 结构：STR = { 语言: { 键: 文案 } }，文案里 {name} 是占位符。
// 加一门新语言 = 加一个子对象，不用动任何业务代码。
// 语言码归一化：zh-hans/zh-tw 都归 zh，en-us/en-gb 都归 en。
// ============================================================
const STR = {
  zh: {
    welcome: "👋 你好 {name}，发 /help 看我能做什么。",
    points: "你有 {p} 分。",
    only_admin: "⛔ 只有管理员能用这个命令。",
  },
  en: {
    welcome: "👋 Hi {name}, send /help to see what I can do.",
    points: "You have {p} points.",
    only_admin: "⛔ Admins only.",
  },
};
const FALLBACK_LANG = "zh";
function normLang(code) {
  const c = String(code || "").toLowerCase();
  if (c.startsWith("zh")) return "zh";
  if (c.startsWith("en")) return "en";
  return FALLBACK_LANG; // 没收录的语言先回退，别硬撑着显示 undefined
}
function t(lang, key, vars = {}) {
  const pack = STR[lang] || STR[FALLBACK_LANG];
  let s = pack[key] || STR[FALLBACK_LANG][key] || key;
  for (const [k, v] of Object.entries(vars))
    s = s.replaceAll("{" + k + "}", String(v));
  return s;
}

// ============================================================
// 【核心模块】用户语言判定
// 优先级：用户手动切换过的（KV lang:<用户ID>）> 客户端 language_code。
// /lang 命令切换时写 KV，之后一直按他选的来。
// ============================================================
async function userLang(env, user) {
  if (env.BOT_KV) {
    const saved = await env.BOT_KV.get("lang:" + user.id);
    if (saved && STR[saved]) return saved;
  }
  return normLang(user.language_code);
}

// ============================================================
// 【核心模块】多语言命令菜单注册
// setMyCommands 带 language_code 参数即只对该语言用户生效；
// 另有一份不带 language_code 的默认注册兜底（见 02 号模块）。
// 命令名本身只能是英文小写，能翻译的只有 description。
// ============================================================
const COMMANDS_BY_LANG = {
  zh: [
    { command: "start", description: "开始使用" },
    { command: "help", description: "查看帮助" },
  ],
  en: [
    { command: "start", description: "Start" },
    { command: "help", description: "Help" },
  ],
};
async function registerCommandsI18n(env) {
  for (const [lang, commands] of Object.entries(COMMANDS_BY_LANG))
    await tg(env, "setMyCommands", { commands, language_code: lang });
}
```

## 接入步骤

1. 把 Bot 里所有硬编码的用户可见文案搬进 `STR`，业务代码里改成 `t(lang, "键", {变量})`。
2. handle() 开头先算 `const lang = await userLang(env, msg.from);`，整条链路往下传。
3. 提供 `/lang` 命令：按钮列出可选语言，回调里把选择写进 `lang:<用户ID>`（回调前缀可自拟，别和 03 号模块的注册表撞）。
4. /setWebhook 时在原有注册后再调 `registerCommandsI18n(env)` 补各语言描述；管理员分级菜单同理按语言各注册一遍（见 02 号模块）。

## 注意点

- language_code 是「客户端界面语言」，不等于用户母语，也有人故意设别的语言——所以手动切换入口一定要有。
- 字典缺词时回退默认语言，别让用户看到键名或 undefined；新加文案先补默认语言，再补其它语言。
- 日期、数字格式也算本地化：签到日期这类文案（见 16 号模块）别只翻文字，格式也按语言习惯走。
- 按钮文字同样走字典，漏翻的按钮最容易被用户截图吐槽，上线前把每个语言包的键对齐一遍。
