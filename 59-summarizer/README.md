# 长文 / 频道总结 Bot

把长文章、长帖子压成「一句话总览 + 要点 + 注意」的 TL;DR。对应 @vustSummaryBot、Summarix 那类产品：抓取层复用 44 的安全抓取，LLM 客户端与 31 同口径。

## 部署要点
同单体三步部署，变量：BOT_TOKEN*、AI_API_KEY*（Secret，OpenAI 兼容口径）、AI_API_BASE（默认 https://api.openai.com/v1）、AI_MODEL（默认 gpt-4o-mini）、WEBHOOK_SECRET。**不需要 KV、不需要 Cron。**
⚠️ 没配 AI_API_KEY 时只会明确回复「未配置」，不会编造摘要。

## 玩法说明
- 私聊发文章链接：SSRF 校验 → 抓取正文（剥脚本/导航/广告区）→ 总结；
- 私聊发长文本（≥300 字）或转发来的频道帖：直接总结文本；
- 群里回复任意长消息发 /tldr：总结被回复的那条；那条里带链接时先抓链接正文；
- 输出格式固定：一行总览 + 3–6 条要点 + 一行「⚠️ 注意」，超长自动分段发送。

## 实现说明
- 长文走 **map-reduce**：超过约 7000 字先按 6000 字切段各出小结，再把小结合并出终版——单次调用装不下时不丢信息的标准做法，代价是多几次 API 调用（代码注释里写明了）。
- 正文提取是正则剥标签的轻量实现，覆盖大多数资讯站；付费墙、登录墙、纯 JS 渲染页抓不到正文时会如实报错，并提示直接粘贴正文。

## 注意事项
- 抓取只认公网 http/https，内网/本地地址一律拒绝（SSRF 防护，与 44 同口径）。
- 摘要质量取决于所接模型；SUMMARY_RULE 是代码里的常量，想换输出风格（如英文摘要、只要三句话）改它即可。
- 每次总结都是真金白银的 API 调用，公开部署建议在前面拼模块 27 的限流，或只在私聊/自有群开放。
